# ADR-009: 2D memory-граф вместо 3D (Three.js), autonomy ladder, second-brain поиск с источниками

## 1. Контекст (The Problem)
`PROJECT_IDEA.md` (Key Feature #9) и `SPECIFICATION.md` (Screen 5) описывают "3D Graph Visualization" на Three.js/Babylon.js для памяти vault (tasks/stakeholders/templates/decisions). Виктор принёс референс — [skilltree.altari.ai](https://skilltree.altari.ai) — и предложил в другом чате заменить 3D-граф на "tree/department layout" как более простой и быстрый.

Я изучил сайт сам (не только по пересказу). Уточнение: то, что там называется "Map", — это **не иерархическое дерево**, а узловой граф (ноды-кружки, связи-линии, тёмный фон со звёздами), просто плоский/2D, а не вращающаяся 3D-сцена. По сути — то же самое, что уже описано в PROJECT_IDEA.md, только без затрат на реальный WebGL 3D-движок.

Также на сайте нашлись два паттерна, которые сильно точнее ложатся на архитектуру Jarvis, чем то, что обсуждалось в присланном пересказе:
1. **Карточка ноды при клике**: описание → "breaks into" (под-компоненты) → "builds on" (зависимости) → "what it replaces" → **лестница автономности** (human-led → human-assisted → fully autonomous, с описанием каждой ступени и ролью человека).
2. **Second Brain поиск**: вопрос → ответ + список документов-источников с переходом к оригиналу.

## 2. Предложенное решение (The Decision)
1. **Memory Graph — 2D, не 3D**: рендерим vault (tasks/stakeholders/templates/decisions/domains) как 2D force-directed граф (например `d3-force` или `react-force-graph-2d` — обычный canvas/SVG, без Three.js/Babylon.js). Клик по ноде → боковая панель с деталями, как в референсе. Цвет по домену (уже заложено в `domains.yaml` → `color_hex`).
2. **Autonomy Ladder вместо булева `autonomous`**: расширяем модель — вместо `autonomous: bool` в `IntentResult`/task — трёхступенчатый статус `human_led | human_assisted | fully_autonomous` с описанием роли человека на каждой ступени (по образцу карточки из референса). Это не просто визуальный твик — меняется поле в `core/intent_router.py` и схема задачи. Детали реализации — отдельная атомарная задача при декомпозиции Phase 3 через `/plan`, здесь фиксируем только направление.
3. **Second Brain поиск**: новый экран/панель — вопрос к vault → ответ (через `context_engine` + LLM) + список конкретных заметок-источников с переходом к оригиналу. Естественное развитие уже существующих `context_engine.get_stakeholder/get_knowledge`.
4. **Dashboard**: KPI-строка + график + список "сигналов" (по композиции референса), без копирования конкретной анимации/карусели — это маркетинговый приём для лендинга, не паттерн рабочего интерфейса.

Код SkillTree не копируем (чужой продукт с лицензией) — берём только визуальные/структурные паттерны, как и договаривались.

## 3. Последствия (Consequences)

### ✅ Плюсы
- 2D force-graph на порядок дешевле в реализации и поддержке, чем настоящий Three.js 3D (нет WebGL-специфичных багов, проще адаптивность, быстрее рендер).
- Autonomy ladder — не косметика, а более точная модель того, что Jarvis и так пытается отслеживать (SPECIFICATION.md → Task Lifecycle → autonomy check), просто в бинарном виде это было беднее.
- Second Brain поиск с источниками — прямое расширение уже готового `context_engine`, минимум нового кода.

### ❌ Минусы / Риски
- Autonomy ladder — это правка модели данных (`IntentResult`, `tasks` schema), не только UI; нужно аккуратно провести через `core/intent_router.py`, `interfaces/api.py`, воркфлоу — задача для `/plan` Phase 3, не тривиальная косметика.
- Референс — маркетинговый сайт продукта, которого, по всей видимости, ещё нет в публичном доступе (waitlist) — часть эффектов (карусель Command Centers) там существует только для презентации, не факт что так же хорошо будет работать как реальный рабочий инструмент.
